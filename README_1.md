# HR AI Screening MVP

## Описание проекта для презентации

`HR AI Screening MVP` — это локальная HR-система для первичного отбора кандидатов с единым сквозным сценарием:

1. HR создаёт вакансию в dashboard.
2. Загружает резюме в `PDF`, `DOCX` или `ZIP`.
3. Система парсит резюме, извлекает профиль кандидата и считает первичный `resume score`.
4. Кандидат получает email-invite со ссылкой на Telegram-бота.
5. После `/start` бот проводит короткий screening-диалог.
6. Ответы кандидата анализируются отдельным `dialog_scoring_service`.
7. В dashboard HR видит:
   - общий `Score`
   - `SCORE SOFT SKILLS`
   - статусы контакта и этап прохождения screening
   - summary по кандидату

### Архитектура

Проект состоит из двух сервисов:

- `hr-ai-screening-mvp` — основной backend и dashboard
- `dialog_scoring_service` — локальный сервис оценки soft skills по ответам кандидата

### Что важно для презентации

- Есть единый пользовательский сценарий от загрузки резюме до soft skills scoring.
- Есть web-dashboard для HR без разрыва между этапами пайплайна.
- Есть локальный Telegram onboarding flow через deep link.
- Soft skills scoring сохраняется в БД и отображается в интерфейсе.
- В `dialog_scoring_service` добавлены:
  - локальный inference без внешнего LLM API
  - RAG-слой по требованиям вакансии
  - multi-agent orchestration
  - lightweight trainable head для адаптации оценки
  - режим под слабое железо

## Оценка по критериям

### Без изменений

- `Презентация` — `0.5 / 1`
  Комментарий: Доделываем до хорошего вида и забираем максимум.

- `Удобство использования` — `1 / 1`
  Комментарий: Есть единый dashboard со сквозным сценарием.

- `Анализ аналогов и ЦА` — `1 / 1`
  Комментарий: Неплохо.

- `Интерфейс` — `1 / 1`
  Комментарий: Интерфейс аккуратный и понятный (таблица кандидатов, статусы, формы).

- `Обработка сложных/неопределённых запросов` — `1 / 1`
  Комментарий: Парсинг, валидация входов, fallback в API-цикле.

### Обновлённые критерии

- `RAG` — `1 / 1`
  Комментарий: В `dialog_scoring_service` добавлен retrieval по описанию вакансии, hard skills и soft skills с выбором релевантного контекста.

- `Агент (1) / Мультиагент (2)` — `2 / 2`
  Комментарий: Добавлены `RetrieverAgent`, `ScoringAgent` и `ScreeningCoordinatorAgent` с разделением ролей внутри scoring pipeline.

- `Инференс модели без API` — `1 / 1`
  Комментарий: В `dialog_scoring_service` используется локальный inference на `sentence-transformers`, без внешнего LLM API.

- `Дообучение модели` — `2 / 2`
  Комментарий: Добавлен lightweight trainable scoring head/calibrator поверх локальных эмбеддингов.

- `Оптимизация под слабое железо` — `1 / 1`
  Комментарий: Добавлены CPU-only runtime, lazy loading, ограничение числа потоков и лимит количества анализируемых ответов.

### Критерий без кодовых изменений, но с формализацией

- `Анализ вычислительных потребностей` — `0 / 1`
  Комментарий: Формализованного расчёта пропускной способности и ресурсной модели в коде нет; в текущем виде критерий лучше оставлять без завышения.

## Итог

Текущая версия проекта сильнее всего выглядит по следующим пунктам:

- единый HR workflow
- понятный dashboard
- Telegram screening
- soft skills scoring в интерфейсе
- локальный ML-сервис с retrieval, агентным orchestration и trainable scoring head

Если защищать проект на презентации, оптимальная подача: показать не только backend и UI, но именно полный путь кандидата от email-invite до появления `SCORE SOFT SKILLS` у HR.
